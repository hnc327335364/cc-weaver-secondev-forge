本规范只在需求涉及后端 E10 标准能力、接口、SDK、Hook 或数据访问时适用。纯前端组件、样式、页面任务不加载本文。

在进入适用的后端业务实现前，先按业务对象路由到对应业务 Skill，再使用该 Skill 的
`scripts/search-api.mjs` 检索结构化 API 契约。检索顺序固定为：

1. 执行 `search` 获取模块和接口候选。
2. 对最终候选执行 `load` 获取接口明细。
3. 需要原始上下文时，再使用同一 Skill 的 `scripts/search.mjs` 检索并加载命中文档。

候选必须通过模块、接口签名、E10 基线和参数契约核验。待决冲突保留在所属业务 Skill，
普通检索排除，显式冲突审计才返回；不同 Skill 的检索分数不得混合排名。

## 执行规范

1. API 候选的模块名与接口名必须来自目标业务 Skill 的 `search-api.mjs search` 结果。
2. 对最终候选执行 `search-api.mjs load`，核对完整模块名、协议、接口签名、参数和版本范围。
3. 结构化契约不足时，使用同一 Skill 的 `search.mjs` 检索原始文档；不得跨业务 Skill 拼接证据。
4. 首次检索无有效命中时，可按 `./.ecode/skills/backend-development/references/api-module-baseline.md` 更换一次模块关键词；冲突审计显式增加 `--include-conflict`。
5. 输出实现前，必须附带检索证据：`module_name`、`interface_name`、`business_api_id`、
   `target_skill`、命中文档与加载章节。
