## 使用方法

对每项填写 `PASS / FAIL / N/A / UNVERIFIED`，并附代码位置、配置、测试报告或运行证据。`FAIL` 以及高风险项的 `UNVERIFIED` 阻断发布。`N/A` 必须说明不可达原因。

## 1. 架构与攻击面

- [ ] `WEB-001` 已列出公网/内网端点、管理端点、消息消费者、定时任务和文件处理入口。
- [ ] `WEB-002` 已标出身份、租户、网络、进程、数据存储和第三方服务信任边界。
- [ ] `WEB-003` 高价值数据与高风险操作已有滥用场景、失败模式和补偿控制。
- [ ] `WEB-004` 默认拒绝未声明路由；健康、指标、调试、Actuator、OpenAPI 和管理接口未意外暴露。
- [ ] `WEB-005` 生产环境关闭调试模式、示例账号、默认口令、目录列表和详细错误页。

## 2. 认证与会话

- [ ] `WEB-101` 所有受保护端点均由统一认证中间件覆盖，未依赖前端隐藏或路由命名。
- [ ] `WEB-102` 登录、验证码、重置密码和 Token 端点有按账号与来源组合的速率限制及告警。
- [ ] `WEB-103` 账号恢复不泄露账号是否存在；重置 Token 单次使用、短期有效并在成功后失效。
- [ ] `WEB-104` 密码采用批准的慢速散列算法和组织参数，不使用可逆加密或通用快速哈希。
- [ ] `WEB-105` 登录及权限提升后轮换会话 ID；注销、禁用账号、改密和高风险事件可撤销会话。
- [ ] `WEB-106` 会话 Cookie 设置 `Secure`、`HttpOnly`、恰当 `SameSite`、最小 Domain/Path 及过期策略。
- [ ] `WEB-107` JWT 固定算法并完整验证签名、issuer、audience、时效；密钥可轮换且不由未验证输入选择。
- [ ] `WEB-108` 管理、资金、密钥、敏感资料与权限变更要求近期认证或更强认证因子。
- [ ] `WEB-109` 认证失败、锁定和恢复流程不会形成账号枚举或可用性攻击。

## 3. 授权与越权

- [ ] `WEB-201` 每个请求均检查“主体 + 动作 + 对象 + 租户”，未把已登录当成已授权。
- [ ] `WEB-202` 对象查询/更新在数据库条件或可靠策略层绑定租户/所有者，防 IDOR/BOLA。
- [ ] `WEB-203` 已验证普通用户不能调用管理功能，低角色不能纵向提权。
- [ ] `WEB-204` 批量、导出、搜索、历史版本、软删除、附件和间接引用执行逐对象授权。
- [ ] `WEB-205` 不信任客户端传入的角色、用户 ID、租户 ID、价格、状态或所有者字段。
- [ ] `WEB-206` 内部 API、队列消费者和后台任务使用可验证服务身份及最小权限。
- [ ] `WEB-207` 授权拒绝和权限变更有审计事件，策略服务异常时默认拒绝。
- [ ] `WEB-208` 已完整识别 `/papi/**`、Public API、Partner API 及所有外部可达同等接口，并以“HTTP 方法 + 精确路径”登记负责人、用途、数据分级、认证、Scope/角色、对象授权、限流和有效期。
- [ ] `WEB-209` PAPI 默认拒绝；不存在路径通配符 `permitAll`、`web.ignoring`、排除 Filter/Interceptor 或其他整段安全链绕过。
- [ ] `WEB-210` 除逐端点批准的公开只读非敏感接口外，PAPI 每次调用均验证可信身份；未登记或审批过期的端点不可访问。
- [ ] `WEB-211` 应用服务层验证主体、动作、Scope/角色、对象所有权和租户边界；未仅依赖网关、WAF、IP 白名单、内网、CORS 或隐藏 URL。
- [ ] `WEB-212` 网关、容器与 Spring Security 对路径和方法的规范化一致；重复斜杠、编码路径、分号参数、大小写/后缀差异、方法替换及直连后端不能绕过鉴权。
- [ ] `WEB-213` 匿名 PAPI 无写操作、敏感数据、对象枚举或间接副作用，并具备精确路由审批、响应字段允许列表、限流、监测和到期复审。
- [ ] `WEB-214` PAPI 响应执行字段最小化和字段级授权，不泄露内部 ID、租户/权限信息、秘密、调试字段或超出 Scope 的数据。
- [ ] `WEB-215` PAPI 记录调用方、端点、对象/租户、授权结果和关联 ID；未认证、越权、枚举、异常频率与限流命中可告警且日志不含凭据。
- [ ] `WEB-216` 负面测试覆盖无凭据、伪造/过期/错误受众、错误 Scope、跨用户/租户、对象枚举、路径/方法变体、匿名敏感访问及绕过网关直连后端。

## 4. 输入、注入与输出编码

- [ ] `WEB-301` 所有输入按类型、长度、范围、格式、枚举和业务状态验证；拒绝未知字段。
- [ ] `WEB-302` SQL/JPQL/HQL/NoSQL 值全部参数化；表名、列名、排序字段和操作符来自固定映射。
- [ ] `WEB-303` 不可信输入不会进入 OS 命令、Shell、脚本、SpEL/OGNL、模板源码、JNDI 或动态类加载。
- [ ] `WEB-304` LDAP、XPath、正则和搜索 DSL 使用上下文安全 API、允许列表和复杂度限制。
- [ ] `WEB-305` HTML 输出按文本、属性、URL、JS、CSS 上下文编码；富文本采用成熟的允许列表净化器。
- [ ] `WEB-306` JSON/JavaScript 嵌入不会形成脚本上下文逃逸；优先通过标准 JSON 响应传输。
- [ ] `WEB-307` 响应头、Cookie、文件名和日志字段拒绝或编码 CR/LF 与控制字符。
- [ ] `WEB-308` 请求 DTO 与 Entity/领域模型隔离，防 Mass Assignment 与过度数据暴露。
- [ ] `WEB-309` 错误响应不包含堆栈、SQL、内部路径、类名、配置或秘密。

## 5. CSRF、CORS 与浏览器安全

- [ ] `WEB-401` 基于 Cookie/浏览器自动凭据的状态变更端点启用并验证 CSRF Token。
- [ ] `WEB-402` GET/HEAD/OPTIONS 不产生业务状态变更；CSRF 豁免精确且有架构证据。
- [ ] `WEB-403` CORS 使用精确 Origin 允许列表；凭据模式不使用 `*` 或任意回显 Origin。
- [ ] `WEB-404` CORS 仅开放必要方法、请求头和暴露头，且不被当作授权机制。
- [ ] `WEB-405` 已设置适用的 CSP、frame 限制、`nosniff`、Referrer-Policy 和 HSTS。
- [ ] `WEB-406` 敏感响应使用恰当 `Cache-Control`，不会被浏览器或共享代理错误缓存。
- [ ] `WEB-407` WebSocket 握手验证 Origin、身份与授权，消息级操作继续授权和限流。

## 6. 文件、路径与内容处理

- [ ] `WEB-501` 上传限制总大小、单文件大小、文件数、名称长度、处理时间与并发。
- [ ] `WEB-502` 文件类型由内容与业务允许列表确定，不信任扩展名或客户端 MIME。
- [ ] `WEB-503` 上传文件服务端重命名，存储于非 Web 根目录/不可执行位置，并按风险扫描或重编码。
- [ ] `WEB-504` 所有文件访问在规范化后仍限制于固定根目录，并防符号链接与路径竞态。
- [ ] `WEB-505` 解压限制条目数、展开总大小、压缩比和嵌套层数，逐项防 Zip Slip。
- [ ] `WEB-506` 下载通过授权对象 ID 定位，内容类型、`Content-Disposition` 与 `nosniff` 安全设置。
- [ ] `WEB-507` 图片、PDF、Office、音视频等解析器在隔离环境运行并有资源上限。

## 7. SSRF、网络与重定向

- [ ] `WEB-601` 出站请求目标由服务端允许列表决定，而非直接使用用户 URL/主机/端口。
- [ ] `WEB-602` 连接时校验所有解析 IP，阻断环回、私网、链路本地、元数据和管理网段。
- [ ] `WEB-603` 默认关闭自动重定向，或每跳重复协议、主机、端口与 IP 校验。
- [ ] `WEB-604` HTTP 客户端设置连接/读取/总超时、响应大小、并发和重试上限。
- [ ] `WEB-605` TLS 证书链和主机名校验启用，未使用信任全部证书的测试代码。
- [ ] `WEB-606` 跳转目标为固定 ID 或允许的站内相对路径，防开放重定向。
- [ ] `WEB-607` Host/Forwarded Header 只信任已知代理重写值，不用于无验证的安全决策或链接生成。
- [ ] `WEB-608` CDN/WAF/反向代理与应用对请求行、Host、Content-Length/Transfer-Encoding、重复头和编码的解析一致；拒绝歧义报文并避免缓存键遗漏安全相关输入。

## 8. 解析器与反序列化

- [ ] `WEB-701` 不反序列化不可信 Java 对象；遗留场景使用精确类过滤及深度/引用/数组/字节限制。
- [ ] `WEB-702` JSON/XML/YAML 等关闭任意类型、多态默认类型和类名实例化。
- [ ] `WEB-703` XML 解析器、Schema、XSLT 均关闭 DTD、外部实体与外部资源访问。
- [ ] `WEB-704` 解析器限制输入大小、深度、字段/节点数和处理时间，防内存/CPU 耗尽。
- [ ] `WEB-705` 反序列化对象执行字段允许列表、取值范围、授权和业务不变量校验。

## 9. 密码学、秘密与隐私

- [ ] `WEB-801` 敏感传输全程 TLS；没有明文回退、弱协议或跳过证书验证。
- [ ] `WEB-802` 敏感数据使用批准的认证加密；IV/Nonce 唯一，密钥与密文分权存放。
- [ ] `WEB-803` Token、验证码、密钥使用 `SecureRandom`；安全比较使用恒定时间能力。
- [ ] `WEB-804` 源码、配置、镜像、CI 日志、URL 和测试数据中无真实秘密。
- [ ] `WEB-805` 秘密来自受控管理服务，具有最小访问权、轮换、吊销和审计能力。
- [ ] `WEB-806` 数据采集、响应字段、日志和保留期符合最小必要原则；删除/导出流程可验证。
- [ ] `WEB-807` 不存在默认/示例密码、默认/示例密钥、硬编码秘密、跨环境复用凭据或配置缺失时的固定秘密回退值；发现任一项即阻断发布。
- [ ] `WEB-808` 生产启动会拒绝空值、占位符、已知默认值和不合规秘密；测试凭据/密钥通过构建与 Profile 隔离，生产路径不可达。
- [ ] `WEB-809` 已提交或发布的秘密按泄露处理并完成吊销/轮换；秘密扫描覆盖源码、历史可达制品、镜像和 CI/CD 配置。

## 10. 资源限制与业务滥用

- [ ] `WEB-901` 请求体、字段、集合、嵌套、分页、批量、导出和响应均有服务端硬上限。
- [ ] `WEB-902` 线程池、队列、连接池和缓存有界，具备超时、背压、取消和隔离。
- [ ] `WEB-903` 重试次数有限并带退避/抖动；非幂等操作使用幂等键或不自动重试。
- [ ] `WEB-904` 登录、搜索、上传、发送消息、下单、兑换、导出等高成本/高价值动作有限流与配额。
- [ ] `WEB-905` 已测试大输入、慢请求、压缩炸弹、复杂正则、深分页和并发竞争。
- [ ] `WEB-906` 价格、库存、优惠、审批、状态机和重复请求校验在服务端且保持事务一致性。

## 11. 配置、供应链与部署

- [ ] `WEB-1001` 依赖与构建插件锁定版本，只从批准仓库获取并验证完整性。
- [ ] `WEB-1002` 已生成 SBOM，并执行 SCA/SAST/秘密扫描；高危可利用问题已修复或有到期豁免。
- [ ] `WEB-1003` CI/CD 凭据最小授权，非受信变更不能读取生产秘密或发布制品。
- [ ] `WEB-1004` 制品与基础镜像来源可追溯、固定摘要并经过漏洞检查。
- [ ] `WEB-1005` 应用使用非 root/低权限账号、只读文件系统（可行时）、最小网络与文件权限。
- [ ] `WEB-1006` 开发、测试、生产身份和数据隔离；生产配置不含测试后门或宽松开关。
- [ ] `WEB-1007` 默认配置安全，配置缺失、解析失败或安全依赖不可用时启动失败或拒绝服务。

## 12. 日志、告警与异常条件

- [ ] `WEB-1101` 认证失败、授权拒绝、权限/密钥变更、管理操作和敏感数据操作均有结构化审计。
- [ ] `WEB-1102` 日志包含主体、动作、对象、结果、来源、时间和关联 ID，但不含 Token/Cookie/密码/私钥。
- [ ] `WEB-1103` 日志对 CR/LF 与控制字符安全处理，访问、完整性和保留期受控。
- [ ] `WEB-1104` 高风险事件与异常模式触发有负责人和响应流程的告警。
- [ ] `WEB-1105` 鉴权、风控、限流、签名和审计组件异常时失败关闭，不返回伪成功。
- [ ] `WEB-1106` 事务与外部副作用在超时、重试、重复消息、乱序和部分失败时保持可恢复一致性。

## 13. 必需验证证据

- [ ] `WEB-1201` 单元/集成测试覆盖未认证、低权限、跨用户、跨租户和批量越权。
- [ ] `WEB-1202` 负面测试覆盖 SQL/命令/表达式注入、XSS、CSRF、SSRF、路径穿越、XXE 和反序列化的适用场景。
- [ ] `WEB-1203` 自动化测试验证大小、时间、并发、重试、解析深度和响应上限。
- [ ] `WEB-1204` 安全配置在生产等价环境验证，包括代理头、TLS、Cookie、CORS、CSP 和错误页。
- [ ] `WEB-1205` 所有 `FAIL/UNVERIFIED` 已有负责人、修复期限和发布阻断状态；例外材料完整且未过期。

## 14. MyBatis 与 MyBatis-Plus 安全

- [ ] `WEB-1301` MyBatis XML Mapper 中所有值参数使用 `#{}` 预编译绑定，不使用 `${}` 处理不可信输入。
- [ ] `WEB-1302` 动态排序字段、表名、列名使用服务端枚举映射到固定标识符，不直接使用前端传入值。
- [ ] `WEB-1303` LIKE 查询使用 `CONCAT('%', #{keyword}, '%')` 而非 `'%${keyword}%'`。
- [ ] `WEB-1304` IN 查询使用 `<foreach>` + `#{}` 而非 `${ids}`。
- [ ] `WEB-1305` MyBatis-Plus 的 `last()`、`apply()` 仅用于固定 SQL 片段，不包含不可信数据。
- [ ] `WEB-1306` `QueryWrapper.orderByDesc/orderByAsc` 的列名经过允许列表校验或 `checkSqlInjection()`。
- [ ] `WEB-1307` 不使用 `@Select("${sql}")` 等形式拼接不可信 SQL。
- [ ] `WEB-1308` 为 `${}` 使用点和 `last()`/`apply()` 使用点编写 SQL 注入负面测试。

## 15. Nacos 配置与服务安全

- [ ] `WEB-1401` Nacos 显式启用认证，使用非默认 Token Secret 和 Server Identity，关闭 User-Agent 白名单，并修改/禁用默认账号。
- [ ] `WEB-1402` Nacos 配置中不存储明文密码、数据库连接串或 API Key，使用加密配置或 KMS。
- [ ] `WEB-1403` 应用使用专用服务账号连接 Nacos，凭据由环境变量或 Secret Manager 注入。
- [ ] `WEB-1404` Nacos 控制台、管理 API、客户端和集群端口仅在可信内网开放，具有精确网络策略。
- [ ] `WEB-1405` 产品版本支持的 Nacos 链路启用 TLS；暂不支持的链路使用专用可信网络、双向网络策略并记录升级计划。
- [ ] `WEB-1406` 配置变更监听器回调只做轻量状态更新，重型重建投递到有界线程池。
- [ ] `WEB-1407` 生产环境 Nacos 命名空间与开发/测试隔离。
- [ ] `WEB-1408` Nacos 配置变更有审计日志和审批流程。

## 16. Redis 安全

- [ ] `WEB-1501` Redis 启用认证，使用复杂密码或证书。
- [ ] `WEB-1502` Redis 监听地址限定在内网，通过防火墙或网络策略限制访问来源。
- [ ] `WEB-1503` 不使用 `KEYS` 命令，使用 `SCAN` + 游标分页。
- [ ] `WEB-1504` 大集合使用 `HSCAN`/`SSCAN`/`ZSCAN` 或有界分页读取。
- [ ] `WEB-1505` 敏感数据存入 Redis 前加密，密钥由 KMS 管理。
- [ ] `WEB-1506` Lua 脚本保持短小、常量级，循环上限固定。
- [ ] `WEB-1507` 大型 Key 删除使用 `UNLINK` 或渐进式删除。
- [ ] `WEB-1508` 设置 TTL 和内存淘汰策略。
- [ ] `WEB-1509` 跨不可信网络或传输敏感数据的 Redis 链路启用 TLS，证书和主机名校验有效。
- [ ] `WEB-1510` 依据实际内存、延迟和操作复杂度定义 big key 阈值并持续监测，不使用无证据的通用固定阈值。

## 19. Spring Boot 与 Spring Cloud 安全

- [ ] `WEB-1801` Spring Security 使用显式 `SecurityFilterChain` 和默认拒绝策略；未声明路由不会因 matcher 顺序、Profile 或自动配置变化而开放。
- [ ] `WEB-1802` Spring Cloud Gateway 鉴权只作纵深防御；下游服务验证服务身份、用户上下文完整性、对象权限和租户边界，并测试绕过网关直连。
- [ ] `WEB-1803` OpenFeign/WebClient/RestTemplate 的目标按信任域固定；不可信输入不能控制完整 URL、服务 ID、代理或重定向，TLS 校验未关闭。
- [ ] `WEB-1804` Actuator、Gateway 管理接口、JMX、heap dump、env、configprops 和 OpenAPI 文档仅暴露必要端点，并与业务网络隔离。
- [ ] `WEB-1805` CORS 在 Spring Security 前使用精确配置处理预检；未通过 `web.ignoring`、整段 `permitAll` 或关闭安全链解决跨域。
- [ ] `WEB-1806` Forwarded/Host 头只信任已知代理重写值；外部请求不能伪造 scheme、host、client IP 或安全审计主体。
- [ ] `WEB-1807` 服务间身份具有最小 Scope、受众、有效期和轮换；服务发现、内网地址和共享请求头不构成身份。
- [ ] `WEB-1808` 超时、有限重试、熔断和降级不绕过鉴权、签名、审计或数据隔离；安全依赖异常时失败关闭。
