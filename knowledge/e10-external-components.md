# E10外部网页嵌入组件接入与权限边界

> 随包解释卡，供内部试用。通用正文、API、案例与已有本地附件先查 [资料导航](../library/catalog.md)，按标题或符号检索后使用 document_id 读取；不依赖维护者电脑路径。本页的核读日期、数量与行号描述当时的整理范围，不代表当前整库验收。详细维护记录不随包，客户工程与现场配置另行提供；知识卡指纹见 [manifest.json](manifest.json)。

本页用于判断“能否在第三方业务系统页面里嵌入 E10 日程、EB、流程或 EM 消息组件”。它不是普通内部 Ecode 脚本：接入至少涉及**前端资源、登录身份、接口可达性、组件参数、业务权限**五部分，不能只交付一段渲染代码。

资料范围为e-code 工具包 **1.3.4** 快照内 `e10-component-js-sdk` 的完整正文（607 行），不是当前线上最新承诺。正文声明基础最低基线 **10.0.2404.01**，Token 方案的服务端对接另要求 **10.0.2406.01**。原文明确不能保证所有内部功能在第三方系统兼容；移动端、浏览器组合及具体组件仍需现场验证。没有执行 SDK、工具包脚本、配置变更或客户测试，也未读取原文远程截图。

## 1. 先选对入口：哪些现有资料可以复用

| 需求 | 应读资料 / 对象 | 不应混用的边界 |
|---|---|---|
| 第三方网页展示 E10 内部组件 | 本页 `window.weaverSDK`，先 `init`，再在初始化成功后渲染或调用功能。 | 不是把内部 Ecode 的 `entry.js` 拷入外站，也不代表整个 E10 页面可任意嵌入。 |
| E10 内部表单字段、明细、保存校验 | E10表单引擎JSSDK文档（来源资料，需在 library 按标题检索） 的当前表单 `formSdk` / `WeFormSDK`。 | 外站加载 `vendor/utils` 不证明任意内部表单实例已经存在。（L01:63–98） |
| 已打开的流程详情页操作 | E10流程详情前端JS-SDK文档（来源资料，需在 library 按标题检索） 的 `getFlowPageSDK()`，区分当前与已持有实例。 | 外站单独渲染流程状态/意见组件，不等于拥有完整流程详情页 SDK 上下文。（L02:67–107） |
| 已有 EB 列表或卡片页面二开 | E10应用建模JS-SDK文档（来源资料，需在 library 按标题检索） 的 `getListSDK` / `getCardSDK`。 | 与外站 `designer.EBComView` 运行组件不是同一层入口；实例是否存在仍须确认。（L03:577–604、1228–1258） |
| 统一认证自定义接口、附件预览下载 | 统一认证接入-自定义接口开发（来源资料，需在 library 按标题检索）、[E10文件ID与文档ID及附件权限专题](e10-file-permissions.md)。 | 前者是服务端认证扩展，不是本页 `authTokenRequest` 的返回合同；后者仍需独立文件/业务权限，不能因组件已显示而省略。（L04:50–108；L05:93–113） |

## 2. 完整接入顺序与责任分工

| 阶段 | 原文可确认的做法 | 开始实施前必须确认 |
|---|---|---|
| 资源可达 | 将 OA 前端 `/build` 资源按原结构部署或代理；也可跨域访问 OA 资源，并设置 `staticDomain`。先加载 `vendor`，再加载 `utils`。（H02:14–36、70–90） | 资源来自目标兼容基线，域名/网络/HTTPS 和版本缓存策略由现场确定；不要固定沿用原例的资源版本查询值。 |
| 全局依赖 | 资源占用 `React`、`ReactDOM`、`ReactRouterDOM`、`mobx` 等全局名。动态加载原例针对 AMD 改写 `window.define`。（H02:36–85） | 宿主已有框架/AMD 是否冲突。原例未给加载失败、重复加载或全局恢复方案，不能当通用生产加载器直接复制。 |
| 身份接入 | 已接统一认证且满足域名限制时走统一认证；否则评估服务端 Token 对接。见 §3。 | 人员映射、当前可信登录会话、租户、过期/退出及错误处理。前端不得自行选择任意用户换取身份。 |
| 接口可达 | 跨域直连、中转接口、Nginx 代理三类。见 §4。 | 静态资源域名与接口域名分别确认；预览跳转等旁路也要测试，不把“页面能打开”当全部网络已打通。 |
| 初始化 / 渲染 | 所有使用 SDK 的页面先配置 `init`；`ready` 表示初始化成功，再调用组件；`error` 处理初始化失败。（H02:93–116、257–270） | `ready` 不是每个组件业务数据已加载或权限已通过的证明；组件挂载回调另见 §5。 |

`init` 中正文明确列出的配置（H02:103–116）：

- 必填 `oadomain: string`；`oatenantkey`、`authTokenApi`、`transferApi`、`apiDomain`、`staticDomain`、`prefixApiPath`、`eteamsid` 均列为可选 string，未给默认值。可选不等于任一接入方案都能省略。
- `enableEcode: boolean` 默认 `false`；打开后会加载 Ecode，须评估已有二开在外站的生效范围，不作为接入必开项。
- `withCredentials: boolean` 默认 `false`；设置本身不授予 CORS、Cookie 或业务访问权限。是否启用由所选认证/跨域方案验证，不一律改成 `true`。
- `authTokenRequest` 是返回 Promise 的钩子，但参数表与正文返回字段冲突，不能只按类型表写实现。正文没有说明它与 `authTokenApi`、直接传 `eteamsid` 同时设置时的优先级。
- MODULE 摘要提到 `apiBaseURL`、`apiAgent`，正文配置表及后续方案实际使用 `apiDomain`、`transferApi`。本页不将摘要中的两名当成已证实别名；需按目标 SDK 实现核对。（H01:33；H02:103–116、187–210）

## 3. 认证：身份获取和业务授权分开

| 路径 | 原文前提与调用关系 | 仍缺少的合同 / 不能做的事 |
|---|---|---|
| 统一认证 | 客户已经对接统一认证，业务系统与 E10 **一级域名相同**；当前用户已通过统一认证登录。`init` 传 `oadomain` 与 `oatenantkey`，内部获取用户认证信息。（H02:120–138） | “业务系统服务端无需开发”只针对这些前提成立的路径，不代表无须身份配置、人员映射或权限测试。租户 key 从授权配置确认，不从截图复制。 |
| 开发平台 Token 接口 | 业务系统未接统一认证，服务端能提供已与 E10 同步的 `usercode`；业务后端调用开发平台认证接口，返回给前端。服务端章节标最低 `10.0.2406.01`。（H02:141–156） | 本正文仅链接另一份开放平台接口说明，没有提供其 HTTP method、鉴权参数、完整请求或失效规则；不能据此生成后端换取请求。密钥与换取逻辑留在服务端。 |
| Token 前端接入 | `authTokenApi` 指向业务后端已实现接口；需要携带业务会话时，可用 `authTokenRequest` 自行请求并返回 Promise。（H02:159–184） | 请求方式和凭据传递由业务后端的实际合同决定；钩子函数不等于允许浏览器直接使用开发平台密钥。 |

**必须裁决的返回字段冲突**：配置表写 `Promise<{ status: boolean, data: { token: string } }>`，服务端说明及钩子示例却写 `status: true`、`data.eteamsid`。正文又将 `eteamsid` 说明为 OA 用户会话 ID，而配置表只写当前登录用户的 `eteamsid`。实施前用目标版本类型/实现与脱敏响应确认字段及语义，**不把普通员工 ID、姓名、`usercode` 或固定样例值充当会话凭据**。（H02:109、115、151–181）

部门接入要求（安全设计约束，不冒充 SDK 已实现能力）：服务端绑定真实当前登录用户和允许的租户，不接受任意前端人员标识代办；认证结果不落日志或通用文档，缓存若有则按用户/租户隔离并遵守实际有效期。退出、会话过期、换人及切租户后必须验证旧组件和请求不沿用旧身份。原文没有给刷新、注销联动或会话销毁 API，不能声称 SDK 已自动处理。

## 4. 接口与代理：选择一条主路径并验证旁路

| 方案 | 已确认配置 | 主要边界 |
|---|---|---|
| 跨域直连 | `apiDomain` 指向可达的 OA 接口域名；网络隔离场景原文提出 Nginx/F5 转发。（H02:189–200） | 资源 CORS 与接口 CORS 分开核对；明确允许的业务来源和实际凭据策略，不用关闭浏览器安全机制作为验收方法。 |
| 中转接口 | `transferApi` 将组件内部请求统一转到业务中转服务。（H02:202–215） | 原文明确不能截获全部请求，已知图片预览重定向可能绕过中转。中转服务实现合同仅外链、未随本模块提供；禁止推断它能自动覆盖下载、重定向或所有认证链路。 |
| Nginx 代理 | 将 `/api`、`/papi` 等目标路径代理到 OA；与宿主接口冲突时，用 `prefixApiPath` 加前缀后匹配/重写。（H02:216–255） | 不照抄面向整站的宽代理配置；现场确认目标路径、方法、请求体、身份与响应跳转。原例将 `/weaver/papi/...` 重写成 `/api/...`，存在语义改变，不能未经合同核对就照用或自动认定应改哪条。 |

FAQ 的三条线索（H02:274–336）应这样用于排查：

1. `baseTeams` 域名错：比较实际请求域名与 `apiDomain` / 代理设计；不能仅凭接口名就切换所有请求域名。
2. CORS 失败：保留失败请求类型、脱敏响应头和来源域，交由受权运维按接入方案处理；没有给出所有环境通用的完整 Nginx 配置。
3. 外站请求 404、OA 内正常：原文给过安全拦截的原因示例，但 404 仍可能来自路由、代理或部署。先核对请求路径、响应和服务端安全日志；**不沿用原文“关闭系统安全拦截”作为部门默认修复**，如需放行由安全负责人限定范围、审批并验证。

## 5. 可用组件、参数与回调

通用入口为 `compRender({ compName, container, params })`：组件名 string、容器 `HTMLElement` 必填，`params` Object 可选；原例用 `.then(success, failed)` 接收结果，但没有返回对象、错误码、失败回调参数或可取消合同。`funcApply({ funcName, params })` 用于调用功能，同样只有 Promise 风格示例，没有完整返回类型。不要据“success”变量名推断业务操作已成功。（H02:340–390）

| 能力 | 正文确认的名称与必要参数 | 可选参数 / 适用边界 |
|---|---|---|
| 日程 / EB 运行视图 | `designer.EBComView`；`pageId: string`、`comId: string` 必填。日程通过已配置的 EB 组件呈现。（H02:394–451） | EB 另列 `className: string`、`client: ClientType`、`comServicePath: string`、`store: CompViewStoreType`、`page: Page`，但这些自定义类型未展开；不猜 `client` 枚举或 store 方法。 |
| EB 挂载 / 自定义渲染 | `mounted: () => void`；`customRender: (viewNode: ReactElement) => ReactElement \| ReactNode`；`onMount`、`onContentMount` 均为 `(dom: HTMLElement, context: any) => void`。（H02:425–437） | 原文分别解释组件 didmount、高阶组件渲染及内部内容渲染；没有证明它们代表数据加载完成、可写入或用户有权限，也未给卸载配对回调。 |
| 流程操作菜单 | `workflow.OpenComps`；`wfCompName: 'WffpOperBtns'`、`showButton`、`routeParam` 必填，示例在 `routeParam` 传 `requestId`。（H02:473–483、508–519） | `topBtnNums: number` 可选，默认 2；`routeParam` 完整结构缺失。`showButton` 表格是 string，示例却是 `true`，需按目标类型裁决。 |
| 流转状态 | `workflow.OpenComps`；`wfCompName: 'WffpStatus'`、`requestId: string` 必填。（H02:485–493、530–538） | 读到状态不代表有流程提交权；没有给独立状态完成回调。 |
| 流转意见 | `workflow.OpenComps`；`wfCompName: 'WffpSignList'`、`requestId: string` 必填。（H02:495–504、520–529） | `hideTabs` 可选，表格仅写数组；示例 `['operationLog']` 不等于完整枚举。隐藏操作日志不是撤销数据读取权限。 |
| EM 加载 / 显隐 / 未读定位 | `funcApply` 名称分别为 `em.addEmWebBtn`、`em.setActiveWeb`、`em.scrollUnreadChat`；第二项要求 `params.activeWeb: boolean`。（H02:545–599） | `activeWeb: false` 仅被说明为关闭主窗口，不等于退出身份、卸载组件或断开消息连接；其他两项原文未列业务参数。 |

页面和组件标识来源：原文提供设计器入口，以及开发者工具从设计器路由和组件 DOM 业务 ID 取值的说明；这属于**目标已配置组件的定位方式**，不是任意 DOM `id` 均可用，也不是权限凭证。（H02:454–467）

原例有两个基础问题，整理时未传播为可执行模板：`weaverSDK.ready(() {` 缺少箭头；通用渲染例写 `deigners.EBComView`，专章及多个示例写 `designer.EBComView`。本页组件名采用专章的 `designer`，仍需目标运行库确认；原始文件不修改。（H02:354–367、378–388、394–445、550–599）

## 6. 生命周期、版本与尚缺的合同

| 缺项 | 对实施和估算的影响 |
|---|---|
| 没有 `destroy` / `unmount` / 取消 `ready` / 释放全局注册合同 | 单页路由重进、容器销毁、重新初始化、多人切换须专项验证。不能杜撰 `weaverSDK.destroy()`，也不能把删除容器 DOM 当作已完成监听、消息连接和会话清理。 |
| 初始化和组件成功/失败的回调参数、重试/超时规则未给出 | 需取得目标 SDK 类型或运行证据后处理；不能编造固定返回字段或无限重试。 |
| `init` 多次调用、多个认证选项的优先级、组件重渲染规则未说明 | 不把单个页面最小示例推广成全站可重入封装；评估重复窗口、请求与全局依赖污染。 |
| 基础版本与 Token 对接版本不同；具体组件无完整版本矩阵 | 不将 `10.0.2404.01` 扩大成全部 Token/组件/移动端功能都支持；以客户基线和补丁另行核验。 |
| 远程截图、流程详细对接和中转服务实现不在本模块正文内 | 本页已消化的是这份正文，不是截图和外链内容；未用截图或链接标题补全参数、效果或代码。 |

## 7. 项目人员准备什么，开发怎样验收

项目人员先提供一张接入清单：业务系统页面与用途、希望嵌入的组件及读写操作、E10 基线、PC/移动范围、认证现状、网络责任人和允许使用的测试账号角色。路径、配置及身份数据按脱敏方式交接；**不需要提供明文密钥或有效会话**。若尚不能确定认证路径，只能做选型评估，不能按“嵌一个组件”直接承诺工期。

开发在授权测试环境逐项验证，记录结果与证据位置；本页没有代做以下验证：

1. **加载**：资源成功、框架/AMD 无冲突，初始化错误可见；重复进入不重复绑定或新增窗口。
2. **身份**：正确用户、正确租户；会话过期、退出重登、换用户后无旧身份沿用；失败不能被固定身份兜底。
3. **数据权限**：允许用户能看/能操作，禁止用户不能读或提交；篡改 `requestId`、`pageId/comId` 仍被后端拒绝或按权限过滤。前端隐藏和渲染回调不能充当该证据。
4. **网络与附件**：主接口、图片预览跳转、文件下载及消息链路按实际使用范围验证；中转成功不代替旁路测试。附件遵循既有专题的业务/文件权限链路。
5. **组件与销毁**：单个组件加载及操作行为，卸载/重进/并存多个容器，PC 与目标移动容器分别记录；来源缺失的卸载合同在解决前不能标为无风险。
