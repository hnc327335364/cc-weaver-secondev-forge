# E10合同模板与条款接口及文件Hook边界

> 随包解释卡，供内部试用。通用正文、API、案例与已有本地附件先查 [资料导航](../library/catalog.md)，按标题或符号检索后使用 document_id 读取；不依赖维护者电脑路径。本页的核读日期、数量与行号描述当时的整理范围，不代表当前整库验收。详细维护记录不随包，客户工程与现场配置另行提供；知识卡指纹见 [manifest.json](manifest.json)。

本页补足合同模块的可检索参数与响应边界。e-code 工具包 **1.3.4** 实际保留了条款、模板两篇正文，共 **5 条 HTTP 接口**；另有 **1 条合同文件赋权 Hook 记录**。两篇正文完整收录不代表接口契约已经完备：认证、失败响应、幂等与部分字段类型仍缺。Hook 记录则只有元信息和调用示例，尚不足以编写可验收的扩展实现。

本次仅静态核对本地归档，没有执行工具包脚本、访问远端链接、调用接口、配置权限或验证客户环境。文中的资料版本、最低基线声明和现场可用性分别看待。

## 1. 按目标选择入口

以下请求路径均来自正文，不将 Hook 名称拼成 HTTP 地址。四条 POST 均标注 `Content-Type: application/json`；GET 查询仅给路径与查询参数表。来源编号见 §7。

| 目标 | 入口 | 文档明确的结果或副作用 | 来源 |
|---|---|---|---|
| 新建条款 | `POST /api/ebd/contract/clauseinfo/save` | 成功样例外层 `data=true`；没有返回新条款 ID 的样例。 | S04:3–34 |
| 更新条款 | `POST /api/ebd/contract/clauseinfo/update` | 以条款 `id` 更新；成功样例外层 `data=true`。局部更新规则未说明。 | S04:36–68 |
| 分页查条款 | `GET /api/ebd/contract/clauseinfo/getListPage` | 成功样例 `data.data` 为列表、`data.total` 为总数；列表元素用省略号代替。 | S04:70–99 |
| 新建合同模板 | `POST /api/ebd/contract/tplinfo/save` | 成功样例 `data.id` 为模板 ID、`data.status=true`。 | S03:3–43 |
| 套用模板并替换书签 | `POST /api/ebd/contract/bookmarks/replace` | `isUpdateField` 默认 1，更新生成文件存放字段；不传 `templateId` 默认套用所有模板。 | S03:45–91 |
| 合同文件赋权扩展 | `EBCONTRACT_FILE_HOOK_001` | 资料标注“手动配置后，自动触发”；没有完整配置、回调与赋权结果契约。 | S07:22–48 |

保存模板与套用模板是两个动作。书签替换接口的 `isUpdateField=0` 仅说明不更新目标字段；该分支仍返回替换后的文件 ID，不能据此当作只读预览或无副作用校验。

## 2. 条款接口：必填范围与查询响应

### 新建与更新

| 字段 | 新建条款正文 | 更新条款正文 | 类型与边界 |
|---|---|---|---|
| `clauseNum` | 必填，条款编号 | 样例列出，未标必填 | 样例为字符串；唯一性、重复编号规则未给。 |
| `clauseName` | 必填，条款名称 | 样例列出，未标必填 | 样例为字符串；长度未给。 |
| `clauseStatus` | 必填；0 关闭、1 启用 | 样例同一枚举 | 样例为数字，未给正式类型表。 |
| `belongId` | 必填，条款二级分类 | 样例列出，未标必填 | 保存/更新样例为字符串；查询参数表是 Long，不据此统一成一种传输类型。 |
| `belongSub` | 所属部门，未标必填性 | 样例列出，未标必填 | 样例为空字符串；单部门/多部门及空值语义均未给。 |
| `clauseContent` | 必填，条款内容 | 样例列出，未标必填 | 样例为字符串；富文本、纯文本与转义规则未给。 |
| `id` | 未列出 | 必填，条款 ID | 样例为字符串；不能用条款编号代替。 |

依据 S04:13–22、46–56。“更新只明确 `id` 必填”不等于其他字段都可省略；未传、空串、null 是保留、清空还是报错，需要补实际契约。新建/更新的响应均只有成功示例 `code=200、status=true、data=true、fail=false`；不能据此定义失败码或断言超时未写入。

### 分页查询

S04:79–84 给出正式查询参数表：`belongId: Long`（非必填，二级分类）、`clauseName: String`（非必填）、`pageNo: int`（必填，页数）、`pageSize: int`（必填，数量）。

来源没有说明页码起点、最大页大小、默认排序、名称精确/模糊匹配或稳定翻页规则。`data.data` 的元素没有字段明细，不能从保存参数反推出查询一定返回 `id`、条款内容或全部字段，也不能据此承诺可完成全量同步。

## 3. 模板保存与书签替换：先核对默认写入范围

### 保存模板

S03:13–28 的示例注释明确了以下字段，但没有正式类型表；除下述枚举外，不把字符串示例提升为固定类型、长度或校验规则。

| 字段 | 必填性与原文含义 |
|---|---|
| `templateName` | 必填，模板名称。 |
| `templateDesc` | 非必填，模板描述。 |
| `belongId` | 必填，模板二级分类 ID。 |
| `sourceType` | 非必填，模板来源；仅示例值 `"0"`，无枚举含义或默认值。 |
| `templateVersion` | 非必填，版本号；示例值 `"1"`，无升级或并存规则。 |
| `templateStartdate`、`templateEnddate` | 必填；示例为 `yyyy-MM-dd HH:mm` 形状，未说明时区、格式校验、有效期边界或起止约束。 |
| `appId` | 必填，EB 应用 ID；`useType=1` 时应如何取值，正文没有说明。 |
| `useType` | 必填；0 为 EB 应用、1 为工作流程。 |
| `operateType` | 必填；原文注明现仅一种 `1=书签匹配`。 |
| `templateFileid` | 必填，文件 ID；未给上传入口、支持格式或附件权限前提。注意原文字段大小写。 |
| `templateStatus` | 必填；0 否、1 是，表示是否使用。 |

成功样例包含外层 `code/msg/status/data/fail`，内部 `data.id` 与 `data.status`。这与条款保存返回布尔值不同；不能套用同一个“取新建 ID”的解析逻辑。模板分类是必填前置数据，但对应“模板分类”文档在本归档中没有正文，无法从本页补出分类查询/创建接口。

### 书签替换

| 字段 | 原文要求 | 实施时需要补齐的判断 |
|---|---|---|
| `workflowid` | 必填，流程 ID | 与请求、业务数据是否属于同一流程/租户；字段名为全小写。 |
| `requestid` | 必填，请求 ID | 请求所处节点、当前人员权限及调用时机。 |
| `dataid` | 必填，数据 ID | 对应哪张表、哪个业务记录，不能根据名称猜成请求 ID。 |
| `isUpdateField` | 非必填；0 否、1 是，默认 1 | 目标存放字段如何配置、覆盖或追加、已有附件如何处理均未说明。样例空串不等于空串与省略等价。 |
| `templateId` | 非必填；不传默认套用所有模板 | “所有模板”的筛选范围、有效期/启用条件和执行顺序未说明；空串与省略是否等价也未说明。 |

依据 S03:55–63。保存模板支持 `useType=0/1`，但替换接口只列出必填的流程/请求/数据 ID；现有正文不能证明无流程的 EB 记录如何调用，也不能凭猜测传空 ID。

S03:67–91 分两种响应：`isUpdateField=1` 的内部结果只示例 `code/msg`；`isUpdateField=0` 另有 `data.data="111"`，注释称“替换后的所有文件 id”。只有单个字符串示例，**多文件分隔方式、返回顺序、部分失败、生成文件到模板的对应关系均未给出**。生成文件、目标字段回写和权限是否同步完成也未说明。

## 4. 文件赋权 Hook：元信息可定位，完整契约仍缺

S06 与 S07 一致标注：名称 `EBCONTRACT_FILE_HOOK_001`，后端 Hook，服务 `weaver-ebuilder-contract-service`，用途“合同文件赋权”，最低支持基线 **10.0.2509.01**，索引状态 `active`。S07 的 raw 文本另写“是否对外：是”。这些是来源声明，不是当前客户已安装、已启用或已授权的证据。

记录的 `params=[]`、`responseParams=[]`，`responseExample` 为空，详情的 `methodSignature/classPath/group/version/requestMethod/contentType` 也为空。顶层 `methodSignature` 只是 Hook 标识，不能当 Java 方法签名；`api-source.md` 只有记录指针，没有补出原始技术契约。

现有示例只展示封装方法 `resetFilePermission(Long fileId, Long requestId)`，把两项放进 params，调用 Hook 执行器；这不证明回调入参必定是两个 Long。请求示例又以 `fileId:"xxx"`、`requestId:xxxx` 表示占位数据，没有正式参数表。尚不能确认：

- Hook 在文件生成、字段回写、流程流转的哪个阶段触发；“手动配置”的具体入口和规则。
- 扩展实现的注册方式、真实回调类型、返回值、异常是否阻断主业务，以及异步/重试规则。
- 给哪些人员、哪些操作赋权；是追加还是重置；旧权限、跨租户访问与撤权如何处理。
- 是否每个文件都触发，以及无流程的 EB 场景是否适用。

原例捕获异常并记录的日志文字是 `getConsultEmployee error`，与合同赋权名称不一致；只把它视为示例可疑点，不推导线上异常处理或复制为实现模板。一般文件 ID、文档 ID 和权限关系继续参考 [E10文件ID与文档ID及附件权限专题](e10-file-permissions.md)，该专题也不能补足本 Hook 的授权对象与触发时机。

## 5. 来源冲突、缺正文与不得外推的结论

| 核对项 | 本次证据与保留结论 |
|---|---|
| 原文 JSON 不是可直接发送的请求样例 | POST 示例带行内注释；模板保存的描述与日期行还有未注释说明，替换响应的两个内部 `code` 键缺引号；条款查询响应列表使用省略号。未将这些样例包装成已验证 JSON。 |
| HTTP 版本缺口 | 5 条 HTTP 入口正文未标最低基线。Hook 的 `10.0.2509.01` 在索引、记录与 raw 中一致，没有发现这些位置互相冲突；不能把该值扩大给 5 条 HTTP 入口，工具包 `1.3.4` 也不是 E10 基线。 |
| 权限与身份缺口 | HTTP 正文未描述认证头、登录态、当前人/租户来源及条款/分类/模板/文件权限校验；Hook “是否对外”不等于免登录。客户项目的 `accessToken` 约定不能直接移植。 |
| 8 篇与 2 篇的差异 | README 记远端目录 8 篇、2 篇有正文、6 篇空正文、下载失败 0；MODULE 同样说明空文档未入索引。当前本地确有 2 篇正文及对应 2 条文档索引。8 篇与下载结果仍是打包方声明，本次未访问远端复验。 |
| 六份缺失正文 | 风险规则、风险类型、规则引用配置、模板分类、条款分类、条款组。**本快照缺少正文只表示证据缺口，不能写成平台不存在这些能力或接口。** |
| 事务与重试缺口 | 保存/更新/替换没有事务、幂等、重复生成、部分失败或回滚说明。不能用“返回样例成功”保证生成、回写与赋权全链路成功。 |

本页没有新增可执行调用代码。后续实施应先补正式参数/响应、基线与权限材料，再在授权测试范围核验。对已有数据的重试先查是否已经保存或生成，避免把无响应解释为未执行。
