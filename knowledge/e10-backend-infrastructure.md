# E10后端基础设施选型与上下文边界

> 随包解释卡，供内部试用。通用正文、API、案例与已有本地附件先查 [资料导航](../library/catalog.md)，按标题或符号检索后使用 document_id 读取；不依赖维护者电脑路径。本页的核读日期、数量与行号描述当时的整理范围，不代表当前整库验收。详细维护记录不随包，客户工程与现场配置另行提供；知识卡指纹见 [manifest.json](manifest.json)。

本页帮助判断“该用哪类平台能力、还缺什么合同才能开发”，不替代完整 API 文档，也不是可直接编译的工程模板。**配置、缓存、MQ、锁与线程池属于后端基础设施，不应统一转到 EB 表单 RPC。** 表单数据业务再读 [E10表单后端调用与数据操作契约补充](e10-form-backend-contracts.md)。

本轮完整核读工具包 `e10-backend-sdk` 的模块入口、场景卡与 834 行正文，对照本库 e10平台定制开发指引（来源资料，需在 library 按标题检索） 的对应章节、后端二次开发规范（来源资料，需在 library 按标题检索）。7 个正文节在空白归一、图片地址替换后相同，属于**同源重复**；增量是选型、冲突识别和上下文边界，不是发现了一套新的 SDK。完整原文仍保留在已有指引，不重复复制。逐文件 SHA、阅读范围和断言行段见 来源核对记录（来源记录，未随包）。

适用版本：e-code 工具包 **1.3.4 是资料包版本，不是 E10 基线**。标准服务调用一节明确写有 `25.0301` 分界；配置、缓存、MQ、锁等其他节没有统一可核实的基线范围。以下“来源明确”仅表示在本地来源中读到，**没有编译、连接客户环境、执行 MQ/Redis/调度测试或验证图片里的接口**。

## 1. 先选能力，再补现场合同

| 需求 | 本地来源给出的候选 | 实现前必须补齐的关键事实 |
|---|---|---|
| 调用标准业务能力 | `SecondRpcUtil` / `SecondSapiUtil`；旧版 SAPI 示例为 `RestClient` | 完整基线、实际方法/路由、参数类型顺序、权限、身份来源、错误返回与超时 |
| 读取环境配置 | `weaver-secondev-service.properties`、配置中心、`@Value` | 单体或微服务、配置归属与注册、刷新方式、缺项处理；配置文件不是打入 jar 就必定生效 |
| 业务缓存 | `ModuleCacheInterface` 注册 + `BaseCache` | 模块与键命名、租户隔离、TTL 单位/默认值、序列化、失效与故障处理 |
| 异步消息 / 广播 | `AsyncClient.send` / `broadCast`、`@AsyncListener` | 队列/主题一致性、消费身份、确认/重投/顺序合同、幂等键及失败处置 |
| 分布式定时执行 | 3.2.4 只有独立文档链接 | 当前来源不能给出注册类、调度注解、参数或并发合同；先补正文/依赖/现场注册事实 |
| 竞争同一业务资源 | `DistributionLockInterface` | `tryLock` 返回/异常、等待与租期单位、默认租期、释放权属、续期与超时后处理 |
| 后端异步任务 | `ThreadPoolUtil` + `LocalRunnable` | 实际公开重载、容量/拒绝策略、任务失败处理、用户租户传递/清理、资源所有者 |
| ID、国际化、日志 | `IdGenerator`、`SystemEnv`、SLF4J | 实际依赖签名、ID 使用约束、语言/租户上下文、日志级别与脱敏 |

共同边界：采用平台封装不等于已有业务权限、事务或幂等。来源没有给出的默认值、返回语义和能力，不从类名或 Java 通用经验补成“官方合同”。

## 2. 关键契约与容易误用的位置

### I01 标准服务：版本分流，不把通用调用器当业务实现

- 来源明确：`25.0301` 及之后展示 `SecondRpcUtil` / `SecondSapiUtil`；之前仅展示 `RestClient` 的 SAPI 调用。不能据此反推旧版 Dubbo 调用方案，也不能把这个分界扩展到全部基础设施。（H02:13–156；L01:1989–2132）
- RPC 实体有服务全名、方法名、`group`、`version`；后两项按目标服务实际配置。参数类型支持示例中的 `Class<?>[]` 或 `String[]`，顺序与实参一致；实体参数示例转 Map，可带 `class` 字段。**服务签名、业务权限、用户身份和租户来源仍须逐接口核实**，一个租户字符串不是授权证明。
- 原例同时声明 `classTypes`、`stringTypes`，最后却传未定义的 `types`；SAPI GET 示例缺两个分号，旧例 `headers`/`request` 也未定义。它们是说明片段，不能原样当编译通过的代码。`Map` 返回示例没有给出业务成功判定、超时或自动重试策略。
- `postSapiForObj` 与 `postSapiForForm` 展示了不同请求形式；后者注明固定 `APPLICATION_FORM_URLENCODED`。按实际接口合同选用，不能因参数相同而互换。

### I02 配置：注册例外与刷新条件要同时保留

- 来源明确：服务配置名为 `weaver-secondev-service.properties`；单体环境修改后需要重启，配置中心管理的 `@RefreshScope` 示例才声称支持自动刷新。**本页不是重启授权**，实际刷新链路要单独验证。（H02:158–231；L01:2134–2207）
- 自定义配置文件不得与标准文件重名，建议 `weaver-secondev-` 前缀；注册类使用固定包 `com.weaver.custom.configcenter`、唯一类名及 `@WeaverConfigCenter.ConfigProperty`，一个服务只引入一次。这个固定注册包是此场景的特殊要求，不能被“全部业务代码放 `com.weaver.seconddev`”机械改写。
- `dataId` 是配置文件名，`group` 是分组，`refresh` 是是否实时刷新；示例里的 `DEFAULT_GROUP`、`"true"` 是显式示例值，不是已证实的省略默认。正文讲自定义文件，示例却填 `weaver-loom-hookreg.properties`，**不要照抄为新业务配置的 dataId**。
- `@Value` 的 `abcd`、`123` 是示例 fallback，不是客户秘密，也不适合直接变成生产缺项兜底。配置归属、必填校验与密钥提供方式应由项目确定。后端规范要求 jar 排除 resources，不能靠把 properties 塞进 jar 代替配置发布。（L02:84–97）

### I03 缓存：模块键不是租户隔离，也不是分布式锁

- 来源明确：模块内定义键常量类并实现 `ModuleCacheInterface`，通过 `baseCache.register(moduleKey, class)` 注册；变量名和值须一致，命名以 `SECONDEV_` 为前缀。`BaseCache` 提供 get/set/del/expire/containsKey 及带 `index` 的重载。（H02:233–398；L01:2210–2375）
- 索引键示例描述 `key:index` 拼接，**没有证明租户会自动加入键**。要按已确认的封装行为设计业务隔离；不能在未核实前假定平台已隔离，也不要机械往所有结构新增 tenant 字段。
- `set(..., 60 * 60)` 只是一个传参例；接口注释没有写 `time` 的单位、未传时间的默认 TTL、`getExpire` 特殊返回值或缓存故障语义。不要把该例直接标成“默认缓存一小时”。
- 示例接收 set/del 的 `success` 却始终返回成功，get 示例读到对象也不返回它；这不是已实现的业务成功判定。索引缓存例使用 `WorkflowModuleKey`，不可直接借用标准模块命名空间。
- 原文允许特殊 setnx/Hash/set 候选使用 `redisTemplate`，但未给 Bean、泛型、序列化、原子组合或锁合同。不能用未经核实的 setnx 片段替代 `DistributionLockInterface`，缓存也不能替代事务或业务权限检查。

### I04 MQ：先对齐名称，别把监听器返回值扩大为投递保证

- Queue 示例是 `AsyncBean.setQueue` + `AsyncClient.send`，消费使用 `@AsyncListener(queues=...)`；Topic 示例是 `setTopic` + `broadCast`，消费使用 `@AsyncListener(topic=...)`，原文称 Topic 具有广播属性。（H02:400–545；L01:2377–2522）
- **示例内部名称未对齐**：Queue 发送/监听 `mq_test`，配置却是 `queue1,queue2,queue3`；Topic 发送 `mq_test_topic1..3`，配置是 `zksh_test_topic1..3`，仅展示一个 `mq_test_topic1` 监听器。不能把几段例子直接组合当完整配置。
- 原例“3 次消息会有 9 条数据”依赖未展开的广播拓扑，不是任意环境成立的数量保证。`AsyncListenerResultBean.setStatus(true)` 只证明示例写入了状态，**不能据此推导 ACK 时点、重投次数、死信、顺序或 exactly-once**。
- `message` 例子只要求可序列化；没有给跨版本消息 schema、业务事务与发消息原子性。落地须明确业务幂等标识、重复/失败处置及可审计的处理结果，不能通过吞异常并一律返回 true 达成“成功”。
- 消费线程不能假定继承 HTTP 当前用户/租户。身份如需随消息提供，应使用经确认且可校验的合同，不信任任意传入的租户值。Topic 示例 `/api/seconddev/...` 也与规范 `/api/secondev/...` 不同；不要复制错误路由或将示例消息全文打日志。（L02:44–58）

### I05 定时任务与身份：缺正文就不编造注册代码

- 3.2.4 仅有独立文档入口；本次未打开外部链接，没有读到调度注册、任务签名、集群互斥、重试、停止或超时实现。（H02:9–11；L01:1940–1942）
- 来源在 `/api` 示例使用 `UserContext.getCurrentUser()`；对无登录 `/papi` 明示不能按此取当前用户/租户。自定义 Action 的 `TenantRpcContext` 也要求请求上下文存在；定时任务或未登录触发时可能不存在。（H02:600–638；L01:2583–2621）
- 这不是“上下文为空就自动放行/自动找管理员”的依据。业务所需身份、租户的合法来源与缺失策略要由实际入口合同确定，明确拒绝、延期或有条件跳过的业务后果；不要替调用方选择。
- Action 例只有 TODO，捕获异常后仍返回 success。不得把它当任务实现、租户传播实现或可靠失败处理。

### I06 分布式锁：原文矛盾尚未消除，不能给可复制成品

- 原文列出统一接口 `DistributionLockInterface`，称可切换 Redis 单机/集群/数据库实现；**核心接口处仅提供图片入口，本轮未核读图片**。（H02:659–703；L01:2642–2686）
- 注释强调 `tryLock()` 必须在 try 外，实际例子却放在 try 内，并在 finally 无条件 `unLock`；`lockKey`、`expireTime` 未定义，是否成功获锁也没判断。这是来源内部冲突，不能只选择其中一种当正确模板。
- 已读文本未证明 `tryLock` 的返回类型/失败异常、等待时长、默认租期、时间单位、续期、可重入、解锁所有者校验。必须先核对现场接口/实现合同，再确定“确认获锁才执行业务、按所有权释放”的正确写法；无证据时不生成接口调用模板。
- 分布式锁不自动提供数据库回滚或消息幂等。还要验证业务超过租期、锁竞争失败、异常退出和跨实例重入时的结果，不能用“已加锁”省略这些验证。

### I07 线程池：不要把注释当默认值，更不能复制平台类

- 原文给出 `com.weaver.common.threadPool.ThreadPoolUtil`，接受 `LocalRunnable`；文字说明 Runnable 场景，不支持 Callable。示例公开入口有 `execute(LocalRunnable)`、`fixedPoolExecute(module,function,LocalRunnable)`，二开模块标识为 `ModulePoolEnum.erkai`。（H02:705–799；L01:2688–2782）
- **默认值冲突**：注释称最大 10、核心 0，所列调用却用 `ModulePoolEnum.OTHER.getMaxThread()`，随后把同一个最大值同时作为 core/max 传入。枚举与工厂实现未提供，不能宣称现场默认就是 0/10。
- 注释说线程池名由 module+function 组成，但所列工厂调用只有 module/core/max；`function` 被写进任务描述。不能推定每个功能必有独立池。可定 core/max 的重载在展示代码中是 private，不应生成业务代码直接调用。
- 该源码片段是平台能力说明，不应在二开 jar 复制一个同名 `ThreadPoolUtil`。原文还提示不要随意关闭平台池；业务取消任务与关闭共享资源不是同一操作。
- 原文关于 Callable 的“自行创建并关闭”与工具包 MODULE“禁止自建线程”的通用门禁存在适用边界待澄清；优先核实既有受管能力及资源治理，不因这句话直接生成自建线程池。队列容量、拒绝策略、异常上报、线程上下文传播/清理、任务超时与取消均未在已读文本中给出。

### I08 ID、国际化和日志：说明层不等于可用实现

- ID：来源描述雪花算法、long、18 位、趋势增长，给出 `IdGenerator.generate` / `generateRangeId`；但例子含中文分号与 `int size` 声明式调用，不能直接编译，也不证明跨节点严格顺序、重试幂等或所有基线始终固定 18 位。（H02:640–657）
- 国际化：示例用租户、人员语言和标签 ID 调 `SystemEnv.getHtmlLabelName`，说明 `{0}` 与数组下标替换；但没有给完整替换重载，且 `res.put("label", );` 缺值。没有登录上下文时如何确定语言/租户仍需合同，不能把示例里的标签 ID 当客户可用标签。（H02:547–598）
- 日志：原文称默认级别 ERROR，列出 `logs/sys-secondev.log`、`logs/sys-err.log`。因此没看到 info 不能直接判定代码未执行；具体环境级别仍需核实。示例的 `publicPermission=true`、记录原始 msg、异常后返回成功都不是通用实施建议。（H02:801–834）
- 部门交付要求：仅记必要的关联标识、阶段、耗时与脱敏错误，不输出 token、Cookie、密钥、完整 SQL 参数、原始业务消息或租户敏感信息。调整日志级别是单独的受控变更，不在排障中自动执行。
