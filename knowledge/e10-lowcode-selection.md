# E10配置低代码与二开选型指南

> 随包解释卡，供内部试用。通用正文、API、案例与已有本地附件先查 [资料导航](../library/catalog.md)，按标题或符号检索后使用 document_id 读取；不依赖维护者电脑路径。本页的核读日期、数量与行号描述当时的整理范围，不代表当前整库验收。详细维护记录不随包，客户工程与现场配置另行提供；知识卡指纹见 [manifest.json](manifest.json)。

先把“要实现什么”拆到表单、页面与动作流，再判断哪一小部分确实需要代码。本文用于首轮选型，不代替客户环境中的配置验证，也不把“没有查到资料”判成“产品不支持”。

## 一、证据范围与结论口径

- 11 篇正文对应的索引记录均为 `hasContent=true`，不是“仅目录”条目。
- 索引和正文头部的逐条原文链接、E10 产品基线均未提供。部分正文另外标了局部功能的版本提示，本文单独保留，不将它扩展成整篇文档的最低基线。
- 本次读取的是离线文字。正文中的图片是远程链接，未下载或核验截图；只有截图而没有文字的选项和表达式，不补写成操作事实。
- `1.3.4` 是e-code 工具包版本，**不是客户 E10 的产品基线**。以下“配置可实现/低代码可实现”表示有正文依据的候选方案，启用前仍需确认现场菜单、权限、版本及样例结果。

本文采用四种结论：

| 结论 | 判断条件 | 首轮输出 |
|---|---|---|
| 配置可实现 | 正文明确覆盖目标；主要是已有对象上的选项、规则、布局设置 | 配置入口、规则范围、待验证样例 |
| 低代码搭建可实现 | 用页面/表单/动作流/连接器组合即可描述完整业务链；接口与数据契约仍可待核实 | 对象及组件组合、字段映射、触发与输出 |
| 局部二开候选 | 已定位配置缺口，且有相关 SDK/扩展路线；只把缺口交给代码 | 缺口位置、扩展入口、必须补齐的运行契约 |

这是一套部门分析口径，不是泛微产品中的四个正式功能名称。

## 二、三个高频主题：能力、入口和限制

### 1. 表单：显隐、计算、查重先查标准配置

**显示属性联动〔S1〕**

- 入口：表单设计器 → 显示属性联动 → 新建规则 → 生效范围 → 触发条件 → 变更对象。
- 正文示例支持依据“是否新建计划”隐藏计划日期和计划内容；生效维度可选当前表单或指定布局。主表触发字段可改变主表或明细字段属性；明细触发字段可改变本行及其他表的显示属性。不要推断为可按任意条件直接改变同一明细表的所有行。
- “隐藏”只隐藏字段名称和控件，仍保留区域及样式；“隐藏行”隐藏整行，正文限定为高级版编辑器布局，并提示合并单元格可能造成异常。空间是否收起必须单独验收。
- 若需求是不同人员看到不同字段，另有多个表单视图分别配置新增、修改、查看权限的产品路径〔S10〕。界面显隐不等于接口数据权限；是否能从查询、导出等入口读取属于另一个验收项。

**公式与字段联动〔S2〕**

- 字段组件路径：组件设置 → 布局属性 → 函数公式。
- 字段联动路径：后台管理的对应表单 → 表单设置 → 字段联动 → 新建联动 → 公式联动。
- 正文举例使用 `DATEADD` 与 `IF` 做条件日期计算，字段联动可设置载入、创建数据、指定字段值改变等触发，并可选全表单或指定布局；字段联动公式还需指定赋值字段。
- 两种方式的入口、触发时机、生效范围不同。不能只确认“计算公式相同”，就认为新建、编辑、首屏旧值、导入都按同一时机执行。
- 原文对大量明细导入的动作流联动另有执行限流提示〔S11〕。该问题不能靠给每行再加一次前端调用解决；先核实批量规模与实际触发链，再评估受控的数据查询或批量方案。本页不据此提供未经元数据验证的 SQL。

**字段查重〔S3〕**

- 入口：后台管理 → 对应表单 → 表单设置 → 字段查重校验 → 新增 → 选择查重字段及处理方式。
- 正文明确区分“禁止提交”与“提醒，可提交”。后一种不能满足“重复数据必须拦截”。
- 产品示例为同一项目只允许提交一次申请；正文未交代并发竞争、API/批量导入是否覆盖、删除后再建、跨租户等边界。要求全入口强唯一时应先验证，不能把页面查重直接承诺为数据库级唯一约束。

### 2. 页面：多个数据展示不等于要从零写前端

**筛选组件联动多个图表〔S4〕**

- 在页面设计器拖入筛选组件 → 选择筛选/高级搜索显示方式 → 添加筛选对象 → 配置筛选字段。
- 正文说明列表、二维报表与图表类数据组件可作为筛选对象；一个筛选组件可绑定不同数据源的多个对象，可设多个字段及自定义分类。
- 页面已存在某数据源图表时，新增同源图表可自动加入筛选对象，新增图表后应复核实际受影响范围。
- 这些证据支持“把同一筛选条件传给多个展示组件”，**不证明不同源数据自动关联、口径一致、行权限一致或外部数据已可访问**。数据口径与数据源准备应分开评估。

**自定义页面复用已有页面〔S7〕**

- 入口：页面设计器 → 基础组件/其他 → 自定义页面 → 配置链接。
- EB 表单、表格和页面在地址符合条件时可组件化展示；也可配置第三方地址进行嵌入。条件控制有多项同时命中时，正文说明按顺序渲染首个满足项。
- 正文局部标注：链接地址类型通过配置传参为 `20250401` 基线支持；ecode 单页地址组件化与指定 ecode 应用 AppId/路径渲染组件标为 `250901` 新增。保留原标记，实施时按现场正式版本说明核对，不能猜成统一的完整版本号。
- PC 路由只能渲染 PC ecode 路由，移动端同理；设计器属于 PC，移动效果需看移动预览或运行页。
- 第三方页面能独立打开不代表允许嵌入或可免登。拒绝嵌入、登录协议及 Cookie 限制应由双方系统负责人确认；本页不建议向 URL 放真实登录凭证，也不把代理或放宽浏览器安全限制当默认方案。
- 正文明确指出：手动修改地址中引用的表单字段可刷新组件，而字段联动等方式赋值可能不刷新；其给出的扩展路线是监听字段变化再刷新自定义页面。这是可定位的**局部扩展候选**，不是必须重写整个页面。

### 3. 动作流：先判断组合能力，再决定是否写服务

**按钮新增数据〔S1〕**

同一产品示例已给出“新增计划按钮 → 按钮触发 → 新增表单数据”的组合路径。按钮条件控制、目标表单字段赋值和创建权限是不同配置项。涉及重复点击或重试时，仍需补业务幂等要求；示例不证明天然不会重复新增。

**动作流直接作为页面数据源〔S5、S6〕**

1. 配置查询第三方接口的连接器。
2. 配置自定义触发动作流调用该连接器，定义输入与输出。
3. 页面列表组件的数据源选“业务模块 → 动作流 → 自定义触发动作流”。
4. 在数据过滤中设置输入参数，在显示字段中选择动作流输出字段。

正文说明此路径可直接展示动作流结果，不必先落地成表单数据〔S5〕。因此“外部查询结果展示成列表”不应默认设计为自建表加全套同步程序。

限制与排错证据：

- 关联类型字段可能传入带 `dataOptions` 的对象，而目标字段需要 `optionId`；正文建议通过 JSONPath 取目标值〔S6〕。应对照实际报文，不能把显示名称直接当主键，也不能照搬示例 ID。
- 同一 FAQ 记录动作流作列表数据源时，终止组件明细 key 需要 `detail1` 的问题〔S6〕。这是该快照所述场景的排查线索，不是所有 ESB 接口或所有明细表都固定叫 `detail1`；需与当前组件契约核对。
- 已读正文没有给出该组合的分页、超时、缓存、连接器认证或高并发上限。涉及这些指标时仍为待确认，不能把“可展示结果”扩写成“任意第三方接口都无代码接入”。
- 如果代码必须主动触发动作流，继续读 [E10自定义动作流触发与迁移注意事项](e10-actionflow-trigger.md)，分别核实 HTTP 与 SDK 的身份、参数、MQ 和迁移条件；不要把页面数据源配置直接当作后端接口契约。

**组件复用与专项包编辑边界〔S8、S9〕**

自定义动作流组件的文档入口是 e-builder → 开发 → 组件，需要动作流管理权限，可封装既有事件/动作的默认值、只读、隐藏和显示名称，并随应用迁出迁入〔S8〕。这里的“自定义”不等同于必须写 Java。

但同包两篇正文存在需要区分的描述：〔S8〕写专项应用迁入后的自定义组件只读不可编辑；〔S9〕进一步描述开发者可在专项包导出前开放部分字段映射、消息对象及终止组件输出参数，让使用者编辑，使用者不能自行开放。〔S9〕还以 `251201` 标注扩展到部分流程组件的能力。

不能简单选择其中一句作为全局规则：需核实对象是“组件定义”还是“动作流中的可编辑参数”、包发布者是否开放、租户版本是否具备功能。原文也没有给出两文所有差异的完整版本对应表。

## 三、六个小需求：首轮应该怎么判

下表是依据上述资料构造的分析练习，不是已完成的客户案例。示例中的业务规则由需求方确认后才能实施。

| 小需求 | 首轮判定与最小方案 | 证据 | 必须核实及第一项验收 |
|---|---|---|---|
| 1. 选“不生成计划”就隐藏计划日期和内容，选“生成”再显示 | **配置可实现候选**：显示属性联动，指定表单/布局和两种条件；不用先写 DOM 脚本 | S1“功能简介、操作说明1” | 要隐藏控件还是连区域收起？验证首屏已有值、选项切换、不同布局；不能仅验新建空单 |
| 2. 按已确认的业务类型及起始日期自动算到期日 | **配置可实现候选**：函数公式或公式联动，按触发时机选择，不固定要求前端二开 | S2“功能简介、操作说明” | 给字段类型及完整计算规则，明确空值、月底/闰日、是否覆盖手工值；先验新建和编辑后的结果 |
| 3. 一个项目只能提交一次保证金申请，重复时禁止提交 | **配置可实现候选；全入口强唯一仍待确认**：配置查重字段，处理方式选禁止提交 | S3“功能简介、操作说明1—2” | “同一项目”用哪个稳定标识？编辑原记录、批量导入和并发是否也须拦截？分别测试，不能只看弹窗 |
| 4. 日期与金额条件同时筛选采购、销售两个图表 | **低代码搭建可实现候选**：两个数据组件加一个筛选组件，逐个映射筛选字段 | S4“功能简介、操作说明” | 两源是否有等价字段与权限？先验证边界值和清空条件，确认不是将采购的金额口径套给销售 |
| 5. 页面按订单号查询第三方交货状态并直接展示，不保存到本地表单 | **低代码搭建候选**：连接器查询 → 自定义动作流 → 列表数据源；认证/响应契约未给齐前不承诺完成 | S5全文、S6问题2 | 提供脱敏请求/响应、鉴权方式、分页和频率；先验一条、无结果、失败。用只读接口，不以“查询”名义触发第三方写入 |
| 6. 表单内嵌已有 ecode 页；联动修改字段后也要刷新，PC/移动都要生效 | **配置复用页面 + 局部二开候选**：先核实自定义页面组件化与端类型；针对联动赋值不刷新，验证 SDK 监听/组件刷新契约 | S7“基础配置、常见问题6” | 给当前 E10 基线、两端路由、字段赋值来源、现有代码。先复现“手动有效、联动无效”，再证明刷新仅发生一次；没有复现就不能预先断言必须写代码 |

不能把这些判定直接转成人天。配置对象数量、权限复杂度、现有资产复用、批量规模与验收边界确认后，再将配置、局部开发、联调和交付分别估算。

## 四、项目人员第一次只需提供这些资料

不用先读完工具包文档，也不要求先写技术方案。先用自然语言回答前三项，其余按需求补：

1. **业务目标与结果**：谁在什么页面做什么，希望看到/写入什么；给一条正常样例和一条不能发生的情况。
2. **当前现场**：E10 版本或基线截图、PC/移动范围、现有功能所在页面及已尝试配置。不要只给“最新版”。
3. **操作边界**：只是看、需要改本条数据、还是会新增其他记录/调用外部系统；哪个测试环境可用于验证。
4. **表单需求再补**：字段显示名、实际标识、类型、主表/明细、已有布局/联动，以及脱敏样例值。暂缺标识可以先评估，不能直接生成可执行代码。
5. **页面需求再补**：已有数据源/视图、筛选字段映射、权限对象；涉及内嵌时补两端路由与现有组件方式，不含登录令牌。
6. **动作流或接口再补**：触发时机、输入输出样例、连接器/动作流配置截图、外部接口鉴权类型、分页/超时及重试要求；凭据用占位符，真实值由获授权人员在现场管理。

资料不足时，助手只追问会改变选型的那两三项，不应要求项目人员一次填完所有技术表格。开发人员拿到资料后再补运行契约，不把缺资料的责任变成“用户自行阅读十几个文档”。
