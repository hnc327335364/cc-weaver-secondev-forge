# 工具执行与权限（供AI按需读取）

使用人员仍只面对 CC 泛微开发助手。由根入口选择 `capabilities.json` 登记的专业 Skill；不要求人员选择八个模块或手动运行命令。

## 依赖与自检

`scripts/cc_tools.py doctor` 只检查本地依赖与工具文件，不联网、不安装、不登录。Python 3.9+ 用于检索、安装和统一入口；本地开发工具需要 Node.js 18+。页面制作另需 Node.js 22.5+、Chrome/Edge 和首次下载运行时。Java工程真实构建需要客户基线依赖、匹配的JDK与Gradle；没有这些条件只能完成骨架/静态检查。

macOS通常用 `python3`，Windows用已核实的 `py -3` 或 `python`，命令参数通过参数数组传递并正确引用路径。不要假设两系统已实测。缺依赖时只说明当前任务所需项，由接收方确认后准备，不自动全量安装或修改全局配置。

## 两类文件必须区分

- `library/` 中的来源代码、规则、正文是不可执行参考，不恢复为运行工具。
- `tools/ecode/` 是本次选取、适配且有逐文件摘要的执行副本；通过 `cc_tools.py` 调用。原始来源不改动。工具参考说明不能覆盖 CC 权限边界或现场项目规则。
- 八个内部专业模块共享同一 `library/`，仅根 Skill 对外注册。来源路由返回的 `skills/...` 资料路径由 `knowledge_lookup.py source` 解析；不为每个模块复制一套字典。

## 本地动作

分析/评审默认只读。用户授权本地实现后，才在指定工程执行初始化、修改、构建或生成报告。不得以“运行本地工具”为由覆盖无关文件、清理历史产物或运行客户项目内未知脚本。前端 --force、替换后端模板URL、关闭TLS校验均不接纳。

`cc_tools.py run <工具> -- <工具参数>` 调用已登记的工具。普通工作不把内部命令、目录和检查过程逐项展示给使用人员，只报告结果及影响判断的缺口。

## 联网与非生产操作

1. 先确认这是开发/测试环境；生产、环境未知、无法确定目标时不执行在线操作。记录实际URL、租户/用户、对象、读取或变更范围；不把资料中的示例当现场配置。
2. 客户登录/读取、依赖或页面运行时下载须在当前任务范围内明确确认。统一入口需要 `--allow-network --environment test|development --confirmed`。这些开关仅记录已确认范围，不能自行生成用户授权。
3. 远端创建、更新、上传校验、导入、同步和发布，另逐次展示变更及恢复办法并获得确认，然后提供 `--allow-remote-write --change-note "本次具体变更"`。上游同步摘要、journal、页面审批文件仍须通过；外层开关不能替代。
4. 通用认证 request、自动发布、覆盖配置默认不接纳，不直接调用底层脚本绕过入口。HR call 无法单凭HTTP方法判断副作用，按可能写入处理。
5. 登录密码只通过安全交互stdin输入，不写命令行或聊天；无法安全输入就暂停登录。默认会话及页面运行时在接收方用户目录的 `.weaver-cc-assistant/` 下，不进入助手分发包或客户仓库；显式位置也须位于包外。工具输出不复述凭据。
6. 不明确响应、超时或首个失败即停止相关链路，先检查目标状态；不自动重放写入。HTTP成功、包导入、实际页面效果和业务验收分别报告。

## 验证表述

随包提供可调用工具，不等于接收方已安装运行环境。页面运行时按CC审核依赖锁安装，不自动使用未知latest；macOS隔离验证已覆盖组件MCP、校验器与预览资源，不包括浏览器、客户业务MCP或发布。安装返回的verification须区分这些层次，installed只表示当前受控安装状态。离线工具测试不证明客户接口可用；安装后，AI按实际任务运行一次必要工具并报告层次，不把新会话读到知识库称为所有专业能力已验证。
