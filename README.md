## 获取与安装

**先获得仓库访问权限，再下载指定版本。** 私有仓库的链接本身不授予权限；尚未授权时，请向维护者提供所用平台的用户名。无需同时注册两个平台。

| 下载入口 | 适用情况 | 获取方式 |
| :--- | :--- | :--- |
| **[Gitee 发行页](https://gitee.com/hou_nachuan/cc-weaver-secondev-forge/releases)** | 国内伙伴优先 | 登录获授权账号，选择 **v0.3.0-rc.3**，下载对应版本源码 ZIP |
| **[GitHub 发行页](https://github.com/hnc327335364/cc-weaver-secondev-forge/releases/tag/v0.3.0-rc.3)** | 已有 GitHub 访问权限 | 登录后在发行页的 **Assets → Source code (zip)** 下载 |

使用完整版本 ZIP，不单独下载 `SKILL.md`。两端提供同版本内容，平台生成的 ZIP 文件名、封装和大小可能不同。

### WorkBuddy

1. 打开 **专家·技能·连接器 → 技能 → 添加技能 → 上传技能**。
2. 选择下载的版本 ZIP，按界面提示导入并启用。
3. 新建对话，调用 **CC Weaver Secondev Forge**，完成下方首次验证。

[查看图文安装步骤](使用说明.md)。仓库根目录即完整 Skill，下载后无需重新整理目录或自行压缩；当前版本的实际客户端导入仍须验证。

### Codex / DSH

将下载文件的本机路径交给具备本地文件访问能力的客户端，发送：

> 请安装 CC Weaver Secondev Forge，ZIP 路径为【本机路径】。读取包内接入说明，核实当前客户端的技能目录，再完整安装。已有同名版本时先说明升级及本地改动处理，不修改客户工程。完成后指导我在新对话验证。

客户端负责核实自己的安装位置。详细流程见 [使用说明](使用说明.md)。

### 首次验证

安装后新建对话并发送：

> 请使用 CC Weaver Secondev Forge。E9 流程表单已有明细首次打开时合计不更新，新增一行后恢复正常。请检索随包资料，说明排查方向，列出实际读取的资料及依据。本次只分析，不修改代码。

**识别技能、读取正文、给出依据**，三项都完成才算当前工具接入有效。

## 开始处理任务

提供 **平台版本、任务目标、现有材料和允许操作的范围** 即可。简单修改直接执行最小流程；复杂任务先核对关键接口和业务规则。

| 场景 | 可直接使用的任务描述 |
| :--- | :--- |
| 需求分析 | 请使用 CC Weaver Secondev Forge，梳理这份 E10 需求，列出需要客户确认的规则、二开范围和验收点。本次不编写代码。 |
| 简单修改 | 请使用 CC Weaver Secondev Forge，这个函数空值显示异常，数字 0 必须保留。只改该函数并做针对性验证。 |
| E9 列表导出 | 请使用 CC Weaver Secondev Forge，按当前查询列表的筛选结果导出。先核实实际取数入口、权限和分页，不猜测接口；缺少依据时指出具体缺口。 |
| 正式交付 | 请使用 CC Weaver Secondev Forge，根据本次已经完成并验证的改动，生成正式开发交付 HTML，注明配置要求及尚待现场验证的内容。 |

## 随包能力

一个注册入口、九个按需专业模块、共享 E9/E10 知识库。包含需求与估算、E9/E10 开发、集成、专项安全与性能评审、环境工程、页面制作及交付支持。

| 内容 | 作用 |
| :--- | :--- |
| `SKILL.md` | 统一入口与任务分流 |
| `skills/`、`references/` | 专业模块、开发约定及场景指南 |
| `library/`、`knowledge/` | 共享正文、索引及知识卡片 |
| `scripts/`、`tools/`、`assets/` | 检索、执行工具和交付模板 |
| `README.md`、`使用说明.md`、`CHANGELOG.md` | 快速开始、完整手册与版本记录 |

发布授权、维护机配置和发版脚本由维护者本地管理，不属于 Skill 的安装内容。

## 使用前提与验证边界

- 完整本地检索及安装助手需要 Python 3.9+，部分开发工具另需 Node.js；WorkBuddy 原生 ZIP 导入本身不要求手动运行这些命令。
- 现场接口、权限和系统版本必须有实际依据；资料示例不能直接替代客户配置。
- 编译、离线模拟、宿主调用与客户验收是不同层次。当前仍为候选版，尚未证明三宿主、双系统及全部业务场景均已通过。
